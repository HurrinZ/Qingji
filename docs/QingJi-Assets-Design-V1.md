# 轻记 1.1：资产账户与记账联动设计

设计日期：2026-11-09。本设计先于开发确定，作为本次实现与验收依据。

## 1. 本次目标

记录各张银行卡、微信零钱、支付宝余额、现金及其他人民币存款。记支出时选择从哪里扣，记收入或退款时选择钱进哪里，随账本记录自动更新账面余额。

所有余额由用户手动录入与维护，不连接银行、微信或支付宝，不申请新的系统权限，不读取支付记录。应用中的“扣款/转账”只改变本地账本，不能移动真实资金。

## 2. 页面与操作

底部导航改为：首页、分析、资产、计划、设置。“记一笔”保留为独立悬浮＋，避免六个按钮挤在一行。

| 页面 | 本次变化 |
| --- | --- |
| 首页 | 增加一行资产合计，可进入资产页；保留月度收支、预算与明细 |
| 资产页 | 资产合计、账户列表、添加账户、账户间转账、已归档账户入口 |
| 账户详情 | 当前余额、期初余额、收支/转账/校准流水、编辑名称、校准余额、归档/恢复 |
| 记一笔 | 支出显示“付款资产”；收入/退款显示“到账资产”；分类与资产分开选择 |
| 分析/预算 | 继续以真实收入、支出与退款统计，不把转账、期初余额或校准计为收支 |
| 备份恢复 | 完整保存账户、关联、转账、校准；恢复摘要增加资产与转账数量 |

账户类型包括：银行卡、微信、支付宝、现金、其他。一个类型可建多个账户，例如“招商银行·工资卡”“工商银行·备用金”。名称可包含末四位作为备注，不要求填写完整卡号。

添加账户填写：名称、类型、当前已有余额。余额允许为0；添加的这笔钱作为该账户的期初余额，不算本月收入。创建后期初金额固定，发现不符时使用“校准余额”，保留调整痕迹。

## 3. 统一余额公式

账户当前账面余额 = 期初余额 + 关联收入 + 关联退款 − 关联支出 + 转入 − 转出 + 校准差额。

仅计算未删除、且开启“同步调整资产余额”的收支记录。余额从流水计算，不另存一个可被重复扣减的余额字段。资产总额为所有未归档账户的账面余额之和；负余额也按实际符号计算。

| 操作 | 账户余额 | 收支分析/预算 |
| --- | --- | --- |
| 建立银行卡，期初10000元 | 银行卡 +10000 | 不计收入 |
| 用微信支付午饭30元 | 微信 −30 | 餐饮支出 +30 |
| 工资到账银行卡5000元 | 银行卡 +5000 | 工资收入 +5000 |
| 银行卡向微信零钱转1000元 | 银行卡 −1000，微信 +1000 | 不计收入/支出，总资产不变 |
| 消费退款到账支付宝20元 | 支付宝 +20 | 原消费分类支出 −20 |
| 把账面余额980元校准为1000元 | 校准差额 +20 | 不计收入 |

记账仍支持“不关联资产”，只记录收支，不改变任何余额。新记账默认最近使用的可用账户，没有时默认首个可用账户；可随时改选。

余额不足不妨碍记录已经发生的消费。保存后以明显提示标记负余额，提醒检查期初余额或漏记收入；不把负余额解释为银行已实际透支。

## 4. 编辑、删除与退款

- 修改金额、收支类型或付款账户时，按最终有效流水重新计算余额。例如30元支出改成50元，只额外影响20元；从微信改为银行卡，微信恢复原金额、银行卡扣除最终金额。
- 删除已联动的支出会恢复余额；删除收入或退款会扣回对应余额；撤销删除恢复原有影响。记录不会因重复保存被再次扣款。
- 退款默认建议回到原支出的账户，也允许选择实际到账的其他账户。累计退款仍不能超过原支出。
- 修改原支出的付款账户，不自动搬动已发生退款的到账账户；退款分类仍跟随原消费分类。
- 攒钱目标继续独立记录进度，不与资产重复相加。目标进度不是新增资金。

## 5. 旧账升级：避免重复扣款

1.0原有收支没有资产信息。升级后全部保留为“未关联资产”，不猜测它们属于哪张卡，也不自动倒扣新填入的当前余额。

例如：微信实际现有500元，旧账里已经记过昨天午饭30元。新增“微信500元”后仍是500元，不自动变成470元。

旧账编辑时可以补关联账户，默认只关联、不调整余额；记账面板明确显示“同步调整资产余额”开关。只有用户主动开启，才把这笔旧账纳入余额计算。新记账默认开启余额联动。没有选择账户时，该开关不生效。

此规则同样适用于导入1.0备份。导入旧格式后账户为空，旧账不影响任何新增账户。

## 6. 转账与校准

转账必须选择两个不同账户、正金额、日期与可选备注。一次数据库事务保存同一条转账记录，来源与去向同时生效。编辑或删除转账时两边同时更新，不拆成一笔收入和一笔支出。手续费需要另记为支出。

校准时输入实际余额，显示调整前、调整后和本次差额，再保存一条独立校准记录。校准也不参与收入、支出、预算或攒钱统计。以后修改旧流水会重新改变账面余额，校准不会悄悄抹掉这些变更；需要时再次校准。

账户流水展示每笔变化、类型、日期及备注，不在补录历史账后伪造逐笔历史余额。

## 7. 账户生命周期

账户可修改名称与类型，历史引用保持有效。账户有余额时不能直接归档，应先转出或校准至0，避免把存款从总资产中隐藏。

余额为0时可归档；已归档账户不出现在新记账选择中，历史流水保留，可恢复使用。修改历史记录如果会改变已归档账户的余额，先要求恢复该账户；仅修改备注或日期不受此限制。首版不提供永久删除账户。

## 8. 数据与升级方案

继续使用Kotlin、Compose和Room。数据库从version1显式迁移到version2，禁止清库升级。应用versionCode升为2、versionName为1.1.0，沿用原签名，支持覆盖安装。

| 数据 | 核心字段 |
| --- | --- |
| AssetAccount | id、name、kind、openingBalance、archived、createdAt、updatedAt |
| Entry新增字段 | assetId可空；affectsBalance；旧数据库迁移默认false |
| AssetTransfer | id、fromAssetId、toAssetId、amount、date、note、createdAt、updatedAt、deletedAt |
| AssetAdjustment | id、assetId、delta、targetBalance、date、note、createdAt、updatedAt、deletedAt |

金额仍按Long“分”保存。余额运算使用整数并检查溢出。账户引用、退款上限、转账来源/去向及归档限制在事务内验证。界面、导出、备份共用余额计算规则。

完整JSON备份升为schemaVersion2，并兼容读取schemaVersion1。恢复前校验所有账户引用、资产类型、转账、差额和旧账标记，事务恢复全部业务数据。CSV收支导出新增资产名称与是否影响余额；转账与校准保留在完整备份中，不混进收支CSV。

## 9. 验收示例

创建银行卡10000元、微信500元、支付宝200元：总资产10700元；用微信消费30元后微信470元、总资产10670元；银行卡转微信1000元后银行卡9000元、微信1470元，总资产仍10670元；该消费退款20元到支付宝后支付宝220元，总资产10690元，净支出10元。

必须验证：新增/编辑/删除/撤销的余额变化；跨账户退款；转账两边联动且不影响统计；校准不算收入；旧账不重复扣款；归档限制；备份1/2兼容；数据库1→2迁移保留旧账；同一备份重复恢复不重复入账；旧签名一致与APK覆盖升级配置。

不属于本次范围：银行直连、自动读取微信支付宝、证券/基金估值、信用卡账单、借贷、外币、资产与攒钱目标自动绑定、云同步。
