02 / 页面与交互规则

  • 底部四个入口：首页、分析、计划、设置；中央“＋”打开记账底部面板，不占独立主页面。
  • 默认支出，金额输入后选择分类即可保存，日期默认当天，备注选填。保存成功立即关闭面板、更新所有汇总，并显示可访问的状态提示。
  • 首页收入、支出、结余明确区分；“结余”是所选期间收入减支出，不代表银行卡余额。未设预算时显示“设置本月预算”，不把零当作无限预算。
  • 分析点击分类进入可编辑的明细；本月对比上月相同日数，历史整月对比上月整月。前值为零时显示“无同期数据”，不生成无穷百分比。
  • 预算超过100%时进度条封顶，另以文字显示超支金额，不能只靠颜色传达。首次创建预算允许选择是否作为后续月份默认值；分类预算的合计不强制等于总预算。
  • 攒钱通过独立进度事件记入；“存入/取出”仅改变目标进度，不创建收入/支出，不推断资产余额。金额不能取成负数，完成目标后显示已达成。
  • 空账本显示空状态与记一笔入口；分析零数据不画虚假趋势。表单校验保留已填内容；删除提供短时撤销；大范围恢复/清空数据需要明确确认。
  • 正式应用采用系统字号缩放、至少48dp触摸区域和 TalkBack 标签；配色默认跟随系统，并提供浅色/深色。本原型先演示浅色方向。

03 / 统计口径：所有页面共用一套计算

指标规则
金额数据库 Long，单位“分”；表单用十进制字符串解析，最多两位小数，禁止 Float/Double 作为记账金额。上限设计为单笔 ¥99,999,999.99，汇总做溢出校验。
支出与退款正式版支持退款关联原支出，按退款发生日冲减支出并归回原分类；累计退款不超过原支出。退款不算收入。本原型仅演示普通支出/收入，不提供退款入口。
预算期间净支出（支出−当期退款）占预算；剩余=预算−净支出；未来日期记录在正式版不纳入“截至今天”统计。计划性账单另行留到后续版本。
结余所选期间收入−净支出。攒钱进度事件不参与收支或预算。
日均本月：月初到今天的日历天数；历史月份：整月日数；自选期间：所选自然日数。本原型以2026-11-09为演示今天。
同比/环比当前月按相同日数对比上月；历史完整月对比上一个完整月；分母为0或无记录时显示无同期数据。正式版对负净支出单独解释，避免误导比例。
日期与删除统计按用户录入的本地账务日期分组，以半开区间 [start, nextStart) 查询；发生时区单独留存。编辑旧账重算对应期间；软删除记录不参加统计。

04 / 安卓技术方案

Kotlin + Jetpack Compose + Material 3 + Room + DataStore + Coroutines/Flow。建议最低 Android 8.0（API 26）；compileSdk/targetSdk 与依赖在建项时按可用稳定版本锁定并实际编译验证，不在设计稿中猜测版本号。

UI → ViewModel → 用例/Repository → Room DAO。Room 是业务数据唯一读取来源；Flow 驱动各页刷新。DataStore 保存主题、提醒偏好等小型配置。统计封装为公共查询/用例：首页、分析、预算共用，避免口径漂移。主线程不做数据库、备份、导出工作。单 App 模块先按 feature/data/domain 包组织，无需第一版就拆成大量 Gradle 模块。

实体核心字段
Entryid(UUID)、type(EXPENSE/INCOME/REFUND)、amountMinor(Long>0)、currency(CNY)、categoryId、accountingDate、occurredAt、zoneId、note、refundOfEntryId?、createdAt、updatedAt、deletedAt?、revision、syncState
Categoryid、name、type、iconKey、sortOrder、isArchived；已用分类仅归档或迁移，不破坏历史引用
Budgetid、period(YYYY-MM)、categoryId?（空为总预算）、limitMinor、updatedAt；期间+预算作用域唯一；默认月预算模板独立保存
SavingsGoal / EventGoal: id/title/targetMinor/targetDate?/archivedAt；Event: id/goalId/amountMinor(正存入、负取出)/date/note；事件合计为进度，事务内校验不为负
ReminderDataStore: enabled、localTime、weekDays、skipIfRecorded；业务配置与系统通知授权状态分开展示

日期、类型、分类建立查询索引；金额写入、退款限额、目标进度更新在数据库事务内校验。Room schema 导出纳入版本控制；升级使用显式 Migration，禁止以清库作为生产升级兜底。针对50,000笔记录验证分页与聚合响应，使用 Paging 或游标分页明细。

05 / 提醒与权限

操作权限/行为
首次打开、记账、分析、预算、攒钱不请求运行时权限，应用私有目录保存数据。
用户主动开启提醒Android 13+ 按需请求 POST_NOTIFICATIONS；旧版本检查应用及通知渠道状态。拒绝后展示未开启状态，其他功能可正常使用，不反复弹窗。
定时通知AlarmManager 单次非精确闹钟 setAndAllowWhileIdle，按本地日期/时间计算下次执行；无需精确闹钟特殊访问。系统省电/厂商限制可继续造成延迟，不承诺具体延迟上限。
重启、手动改时间/时区重建下一次提醒；RECEIVE_BOOT_COMPLETED 为清单普通权限，无运行时授权弹窗。系统强制停止后不保证提醒，下一次打开应用时修复调度。
备份与恢复使用系统文件选择器（SAF），仅访问用户选中的文件，不申请全部文件或广泛存储权限。

默认提醒建议21:30，关闭状态不调度。触发时重新检查通知权限、开关、星期和跳过条件；当天已记账则跳过。已超过当天23:00的延迟提醒不补发，不在第二天发送昨天的提醒。通过“提醒日期+规则版本”去重；无论是否发出，都重新按当前时间计算未来下一次。修改时间/关闭后取消旧 PendingIntent；通知只显示“今天的账记好了吗”，点击打开记一笔。无需常驻前台服务、无障碍、短信、联系人、定位、悬浮窗或忽略电池优化授权。

06 / 本地可靠性、备份与后续同步

  • 正式版默认不接网络和分析 SDK；明确配置 Android 系统备份规则，避免“本地保存”时未经说明被系统云备份。卸载前提示先导出。
  • 完整 JSON 备份包含 schemaVersion、导出时间、币种、所有业务实体与配置；CSV 仅用于表格查看，不作为完整恢复格式。导出可能含私人收支，文件分享由用户自己决定。
  • 恢复先校验大小、版本、字段、唯一 ID、分类/退款外键、金额范围与目标进度；先生成恢复摘要，再由用户确认。一次数据库事务替换，失败回滚；导入前自动创建本地恢复快照。重复导入不重复入账。
  • 云同步第二阶段再设计账号、服务端与冲突协议。首版预留 UUID、revision、updatedAt、deletedAt、syncState；未来采用变更队列、服务端游标与幂等写入，本地始终先读写；冲突用服务端版本检查和显式解决，避免只按手机时间静默覆盖。
  • 本原型使用浏览器 localStorage 保存虚构演示数据，浏览器清理会丢失；这是交互验证，不等同 Room 可靠性、系统通知或原生性能验证。请勿输入真实敏感财务数据。
